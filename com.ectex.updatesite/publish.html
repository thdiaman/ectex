Publishing this site

For maintainers: rebuild the update site and put it on a web server.

What is in the folder

The com.ectex.updatesite project is both a p2 repository and this small website:

PathPurpose
features/, plugins/, content.jar, artifacts.jarThe p2 repository Eclipse reads. Generated; do not edit by hand.
index.html, usage.html, publish.html, style.cssThis website. Static files.
category.xmlDefines the category shown in the Install dialog.
build/build-site.bat, build/build-site.sh, build/BuildSite.javaRebuild the repository (see below). The two scripts just start BuildSite.java.
dist/ectex-updatesite-<version>.zipOffline copy of the repository for Add… > Archive….

Rebuild

Requirements: a JDK 17+ (javac and jar on the PATH) and an Eclipse that includes the p2 publisher tools (an Eclipse SDK or PDE install does). No PDE project import and no Maven are needed.

:: Windows
cd com.ectex.updatesite\build
build-site.bat --eclipse-home "C:\Program Files\eclipsesdk"

# Linux / macOS
cd com.ectex.updatesite/build
sh build-site.sh --eclipse-home /path/to/eclipse

Instead of --eclipse-home you can set the ECLIPSE_HOME environment variable. The script compiles com.ectex.plugin, replaces .qualifier in the versions with a timestamp, publishes the plug-in and the com.ectex.feature feature, adds the category, and writes the zip. Every build replaces the previous one, so the repository and dist/ always contain a single version (installed copies update to the newer build); add --keep-old to keep the older versions next to the new one. Run it with --help to see all options.

To release a new version number, change Bundle-Version in com.ectex.plugin/META-INF/MANIFEST.MF and the version values in com.ectex.feature/feature.xml (both x.y.z.qualifier, identical), then rebuild.

The content is not signed, so Eclipse shows an “unsigned content” warning on install. Signing requires a code-signing certificate and the jarsigner tool.

Host it

Any static web server works. Copy the contents of the com.ectex.updatesite folder (everything except build/ and .project is needed) to the server so that content.jar is directly under the published address. Users then add that address in Help > Install New Software…. The address must be served over plain file download with no redirects to a login page.

GitHub Pages (how this site is published): the repository thdiaman/ectex contains a workflow, .github/workflows/pages.yml, that publishes this folder (without build/, dist/ and .project) whenever files in it change on main. Enable it once under Settings > Pages > Build and deployment > Source: GitHub Actions. The update-site address is then https://thdiaman.github.io/ectex/. For another repository use https://<user>.github.io/<repo>/.

Release routine: rebuild, commit the changed files in this folder, push; attach dist/ectex-updatesite-<version>.zip to a GitHub release if you want to offer the offline copy.

Optional: build from inside Eclipse (PDE)

The projects are also PDE projects. After importing com.ectex.plugin, com.ectex.feature and com.ectex.updatesite into a PDE-enabled Eclipse, you can open category.xml and use its Build All button, or export the feature through File > Export > Plug-in Development > Deployable features. This route has not been tested; the build script above is the verified way. (The .bat launcher was tested on Windows, and the .sh launcher through Git Bash on Windows; it has not been run on Linux or macOS.)

Try the site locally

In Eclipse: Help > Install New Software… > Add… > Local… and choose the com.ectex.updatesite folder.
