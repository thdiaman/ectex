Usage guide

Everything you need after installing EcTeX.

Editor and PDF Preview

.tex files open in the EcTeX LaTeX Editor. The PDF Preview view follows the active .tex editor and shows the PDF with the same base name from the same folder. If it is missing, open it with Window > Show View > Other… > EcTeX > PDF Preview; if it opens somewhere unexpected, use Window > Perspective > Reset Perspective. You can drag the view anywhere.

In the PDF Preview: mouse wheel scrolls, Ctrl+wheel (or + / -) zooms, and the right-click menu has Fit Width, Zoom In and Zoom Out.

Build

Default keyCommand
Ctrl+F2Build PDF: saves the files of the project, runs the LaTeX engine once (by default pdflatex -interaction=nonstopmode -file-line-error -synctex=1), and reloads the PDF if it succeeded. It runs on the project's main file if one is set. Fast, for everyday editing.
Ctrl+F3Run Bibliography Tool: runs BibTeX or Biber (your choice in the preferences) on the document or main file. It needs the .aux file from an earlier build.
Ctrl+F5Build All: runs the sequence chosen in the preferences and stops at the first error. With a bibliography: LaTeX, bibliography tool, LaTeX, LaTeX. Without one: LaTeX, LaTeX. The PDF reloads at the end.

Output goes to the EcTeX Build console (one console per run, with a header for each step). LaTeX errors become problem markers in the editor and the Problems view.

Choosing the tools (Window > Preferences > EcTeX)

  • LaTeX engine: pdflatex (default), xelatex, lualatex, or type any command or a full path. The arguments field holds the options passed before the file name.
  • Bibliography tool: bibtex (default) for documents that use \bibliography{...}, or biber for biblatex with backend=biber. EcTeX does not guess: if the tool does not match the document, the bibliography step fails and the console says what to check.
  • Build All runs: LaTeX, bibliography tool, LaTeX, LaTeX (default), or LaTeX, LaTeX for a document without a bibliography. The bibliography step fails on a document that has none (BibTeX reports “I found no \citation commands”), so choose the shorter sequence for those.

LaTeX projects, the EcTeX menu and the LaTeX perspective

A LaTeX project is a project with the LaTeX nature; it is what lets a project have a main file. Everything else works without it: .tex files in any project open in the EcTeX editor and build on their own.

  • EcTeX menu in the menu bar: always visible, with items disabled when they do not apply. It has New LaTeX Project…, Open LaTeX Perspective, Build PDF, Build All, Run Bibliography Tool, Forward / Inverse Search and the formatting commands.
  • New project: File > New > Other… > EcTeX > LaTeX Project, or EcTeX > New LaTeX Project…. The wizard creates a LaTeX project with a starter main file (already set as the project's main file) and, if you want, references.bib, and offers to switch to the LaTeX perspective.
  • Existing project: right-click the project > Configure > Convert to LaTeX Project. (A .tex file in a plain project also offers EcTeX > Convert Project to LaTeX Project in its right-click menu.) Remove LaTeX Nature turns it back into a plain project and clears its main file.
  • LaTeX perspective: Window > Perspective > Open Perspective > Other… > LaTeX, or EcTeX > Open LaTeX Perspective. It shows the Project Explorer on the left, the editors in the middle, Problems and the EcTeX Build console below, and the PDF Preview to the right of the editors once you open a .tex file.

Documents with several files (main file)

When a document is split over several files (main.tex with \input{chapters/ch1} and so on), tell EcTeX which file is the main file. This needs a LaTeX project:

  1. If the project is not a LaTeX project yet, right-click it and choose Configure > Convert to LaTeX Project.
  2. In the Project Explorer (or Navigator / Package Explorer), right-click the main file, for example main.tex. You can also right-click inside that file in the editor.
  3. Choose EcTeX > Set as Main File.

The main file is then shown as main.tex [main file] in the explorers, so you can always see which file of the project it is. The setting belongs to that project only; other projects are not affected.

From then on, in every .tex file of that project:

  • Build PDF, Build All and Run Bibliography Tool work on the main file, in its folder. Before building, EcTeX saves all unsaved files of the project, so edits in the chapters are included.
  • The PDF Preview shows the main file's PDF and names the document under its tab (“Document: main.tex”). Moving between the files of the project keeps the PDF and its scroll position.
  • Forward search (Ctrl+Space) works from a chapter, and inverse search opens the chapter that produced the text.
  • LaTeX errors become problem markers on the file that contains them, not only on the main file.

The setting is stored per project in .settings/com.ectex.plugin.prefs, so it can be committed with the project. To remove it, right-click the main file or the project and choose EcTeX > Clear Main File; each file is then built on its own again. There is one main file per project: to build a different document of the same project, set another main file or clear it first. Without a main file nothing changes; every file is built on its own.

Jump between source and PDF (SyncTeX)

  • Source to PDF: put the caret on a line and press Ctrl+Space. The PDF scrolls to the spot and highlights it briefly.
  • PDF to source: Ctrl+click on the text in the PDF Preview, or point at it and press Ctrl+Space. The editor jumps to that line.

Sync uses the .synctex.gz file written by the build. If you compile outside Eclipse, add -synctex=1.

Editing shortcuts

Default keyInserts
Ctrl+B\textbf{}
Ctrl+I\textit{}
Ctrl+U\underline{}
Ctrl+Shift+E\emph{}
Ctrl+Shift+M$ $ (inline math)

With text selected, the command wraps the selection and puts the caret after it; without a selection it inserts the empty pair and puts the caret inside. On macOS, Ctrl in these defaults is Cmd.

Configuration

  • Tools: Window > Preferences > EcTeX sets the LaTeX engine, the bibliography tool (BibTeX or Biber), the Build All sequence, their arguments and the synctex command (see Choosing the tools). Use a full path if Eclipse does not see a program on the PATH.
  • PDF Preview (experimental): Sharp text on high-DPI screens in Preferences > EcTeX. On by default. When on, pages are rendered at the real pixel density of the screen they are shown on, which makes text crisp on scaled screens (125%, 150%, 200%). It uses several times more memory per page and re-renders when you move the window to another screen. Turn it off if pages look wrong or Eclipse feels slow. If memory runs out, EcTeX turns it off by itself for the rest of the session and says so in the status line.
  • Shortcuts: Window > Preferences > General > Keys, then filter by EcTeX. Every command above can be rebound or unbound there. The keys shown in status-line messages always follow your bindings.

Troubleshooting

“Could not run …”

Eclipse cannot find the LaTeX engine or the bibliography tool. Make sure your TeX distribution is installed, restart Eclipse so it sees the updated PATH, or enter the full path in Preferences > EcTeX.

“bibliography tool FAILED” in the build console

Check Preferences > EcTeX: choose BibTeX for \bibliography and Biber for biblatex with backend=biber; the document must have a bibliography. For a document without one, set Build All runs to LaTeX, LaTeX.

Ctrl+Space or Ctrl+click does not jump

Build once with Ctrl+F2 so the .synctex.gz file exists and matches the current text, and make sure synctex is available. The status line shows the reason when a jump fails. Edits since the last build can shift line numbers.

A shortcut does nothing or triggers something else

Open Preferences > General > Keys, filter by the key, and look for conflicts in the Conflicts column. Some systems reserve Ctrl+Space for switching input languages; rebind Synchronize in that case.

“This file has no \documentclass” after a failed build

The file is probably a chapter of a larger document. Convert the project to a LaTeX project if it is not one yet, then right-click the main file and choose EcTeX > Set as Main File.

“The main file … does not exist”

The main file stored for the project was renamed, moved or deleted. Right-click the right file and choose EcTeX > Set as Main File, or right-click the project and choose EcTeX > Clear Main File.

“Project … is not a LaTeX project”

A main file needs a LaTeX project. Right-click the project and choose Configure > Convert to LaTeX Project, then set the main file again.

The PDF Preview is blank after a build

Look at the EcTeX Build console: if pdflatex failed, the previous PDF stays displayed.

Known limits

  • A project has one main file. To build another document of the same project, set another main file or clear it first.
  • A main file can only be set for files that belong to a project in the workspace, not for files opened from elsewhere on disk.
  • On high-DPI (scaled) screens the PDF Preview renders pages at the real resolution of the screen, which keeps text sharp but uses several times more memory per page. This is the experimental setting Sharp text on high-DPI screens (Preferences > EcTeX, on by default); if memory runs out, EcTeX switches to normal rendering for the rest of the session.
  • The PDF Preview has no text search.
